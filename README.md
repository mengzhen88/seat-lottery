# 好位 · 一次性邀请抽签（v2，待部署后端）

本版本替代旧版「预先填写五人名单、预分配结果」流程。

## 使用规则

- 发起人创建一轮，系统发出五个不同的专属邀请链接；无需填写其他人的名字。
- 每个人仅拿到一份邀请，打开后只输入自己的名字，点击时由服务器从剩余工位中随机抽取。
- 候选工位固定为 178、180、181、182、183。
- 每份邀请只能创建一条抽签记录。重复点击、并发提交、换名字、换设备均返回原始结果。
- 不同邀请不能分到同一工位。重复姓名也不会占用第二份邀请。
- 发起人通过私密管理链接重新获取五份邀请及使用情况。参与者只可查看自己的姓名、工位及全轮占用进度。
- 「每人一次」以每人持有的一份邀请为边界，无法阻止某人同时拿到其他人的邀请；因此五份必须分别发给五个人。
- 管理链接和邀请都属于访问凭证，不要放进公开仓库、公开群或截图中。

## 结构

- `index.html` / `style.css` / `app.js`：GitHub Pages 静态前端。
- `config.js`：后端部署成功后填入 Worker 的 HTTPS 地址，目前留空，确保不会回退到浏览器本地抽签。
- `backend/worker.mjs`：无 npm 运行时依赖的 Cloudflare Worker。
- `backend/schema.sql`：D1 表结构及唯一约束。
- `backend/wrangler.jsonc`：CLI 部署模板，数据库 ID 必须替换为实际创建的值。

如果通过 GitHub 网页一次性上传，后端文件可能置于仓库根目录。此时 `wrangler.jsonc` 的 `main: worker.mjs` 仍适用，表结构文件为根目录的 `schema.sql`。

## 部署前的最后一步

1. 登录 Cloudflare。
2. 创建 D1 数据库 `good-seat-lottery`，在控制台执行 `schema.sql`。
3. 创建 Worker `good-seat-lottery-api`，部署 `worker.mjs`。
4. 将数据库绑定给 Worker，变量名必须为 `DB`。
5. 验证 Worker `/health` 返回 `ok: true`，再跑一次五份测试邀请的抽取。
6. 将生产 Worker 地址填入 `config.js`，在独立分支完成预览后合并到 main。

不要将未配置后端的分支发布为正式版，也不要继续使用旧版 `#draw=` 邀请链接。本版会明确拒绝旧链接。

## 已完成的检查

实际执行 Worker 路由代码，使用 Node 内置 SQLite 模拟 D1，校验：

- 创建邀请时不存在预分配记录。
- 五份邀请并发抽签得到五个不同工位。
- 同一邀请 20 次并发提交只产生一次分配。
- 修改姓名和跨设备重试保持原始姓名与工位。
- 重复姓名失败不会消费新的邀请。
- 跨轮邀请、错误管理凭证、错误来源请求被拒绝。
- 另外 15 轮并发抽取无重复。
